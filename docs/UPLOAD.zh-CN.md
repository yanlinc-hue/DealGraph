# 导入资料、连接模型与保存工作台

先选对入口：**「导入聊天」读会话 JSON；「导入关系资料」读 DealGraph 关系资料；「打开文件」恢复加密工作台。** 文件后缀相同也不代表格式可以混用。

## 文件格式

目前支持单会话 JSON v1，每个文件对应一个会话。它是应用输入约定，**不是微信官方导出格式**。网站不自动读取微信、不提取应用密钥、不读取 iPhone / iCloud / iTunes 备份，也不解析微信迁移包。你需要已有合法授权的导出资料，按下面规范转换后再导入。

下面是完整、全虚构的最小示例：

```json
{
  "wxid": "wxid_SYNTHETIC_DEMO_CHAT",
  "name": "虚构项目讨论",
  "format_version": 1,
  "messages": [
    {
      "ts": 1788829200,
      "time": "2026-09-08 09:00:00",
      "from_id": "wxid_SYNTHETIC_DEMO_PERSON",
      "from": "示例联系人",
      "type": "文本",
      "type_id": 1,
      "text": "梁奕担任昱澜生物董事长。"
    }
  ]
}
```

字段按严格白名单校验：

| 层级 | 字段与约束 |
| --- | --- |
| 根对象 | 恰好 `wxid`、`name`、`format_version`、`messages`；版本必须是数字 `1`，消息必须是数组 |
| 每条消息 | 恰好 `ts`、`time`、`from_id`、`from`、`type`、`type_id`、`text`，不能缺项或加入额外字段 |
| 时间 | `ts` 是 Unix **秒**整数；`time` 是北京时间 `YYYY-MM-DD HH:mm:ss`，二者必须对应 |
| 类型 | `type_id: 1` 是文本；其他类型不会进行图像、语音或文件内容识别 |
| 文本和标识 | 名称、正文、标识使用字符串；请勿把毫秒时间戳或整份备份编码塞进这些字段 |

原文件应另行备份。转换时保留否定、更正及其顺序，不能只抽取肯定句；同名对象不要在转换阶段未经核对合并。可参考仓库中的[73 条虚构示例](../public/examples/wechat-noisy.synthetic.json)。

## 四步导入

### 1. 选范围，检查真正会发送什么

点击「导入聊天」→「选择聊天文件」。选择会话和北京时间起止日期，逐条排除或编辑家庭、健康、地址等不必要内容。修改只影响本次导入，不改原文件。

打开「实际待发送文本」检查结果。原始微信标识会移除，可辅助隐藏手机号、邮箱、长号码和常见密钥，也能设置自定义隐藏词；姓名和正文仍可能敏感，不保证完全匿名。只在浏览器选择文件和预览时，不发送给模型。

**只分析商业关系，不等于自动删除日常正文。** 未排除的生活内容仍可能包含在上传文本中。图片、语音、文件和分享卡片暂不解析。

复现实测虚构示例时，将截止日期设为 **2026-09-09**；更晚的测试消息应被排除，默认日期会随使用日期变化。

### 2. 第一次同意：发现节点

点「检查完毕，连接大模型」，选择服务商和模型，把自己的 API 密钥填进密钥框，再点「临时配置密钥」。不要把密钥放进聊天、截图、配置文件或 Git。

核对发送内容、服务商和费用说明，勾选本次同意后，点击「发送并发现节点」。这一步上传预览文本，产生费用，只返回候选人物、机构和项目。

默认使用 OpenAI / GPT-4o，也可选择页面支持的其他服务商。密钥必须属于选定服务商；通义千问选项使用北京地域密钥，不自动切换地区。配置密钥或检查服务不代表密钥有额度。

### 3. 人工确认身份

检查姓名、机构、项目、别名及被排除项提示。只有确认同一身份时才合并重复候选；同名不同人不能强行合并，身份不清应继续核对。遗漏参与方可以依据原文补充，不能凭印象编造节点。

**移除候选只改名单，不会从待发送正文中删除姓名。** 如不允许上传该姓名，返回材料页编辑或隐藏。

勾选已检查名单后点「确认名单，继续」。关系分析只允许连接确认名单中的节点；漏节点会导致漏关系。

### 4. 第二次同意：解析关系

再次核对同一份文本、确认名单、服务商和模型，再同意并点「发送并生成商业关系图」。这是第二阶段，**另行上传、另行计费**；每阶段可能分成多批。

成功后新增独立资料集，旧客户与笔记保留。同名对象不跨资料集自动合并。返回修改名单无需再次付费发现；返回修改材料会作废旧名单及同意。

取消、超时或校验失败不以部分结果覆盖原图；程序不自动付费重试，但已经处理的请求仍可能计费。遇到错误先核对提示，不要连续反复点击。

## 关系如何理解

关注有向两端、关系类型、项目范围与引荐人，不能仅看是否连线。客户页可查看关系速览，项目页看参与方与跟进，关系页支持 2D / 3D 和筛选。

| 状态 | 含义 |
| --- | --- |
| 明确记录 | 达到工具的来源支持条件，不等于外部真实性认证 |
| 待确认（review） | 单份聊天的肯定、计划或待定信息不能当成已核实交易 |
| 历史 | 原文表明已经结束的关系，不代表现在仍有效 |
| 有分歧 | 存在冲突或更正待处理，不能只采用较早说法 |
| 不采用 | 否定或不应采用的记录；客户速览可能隐藏，关系筛选与保存结果保留状态 |

项目阶段和“已发材料”等管理记录由你确认，不自动变成交易事实。家庭闲聊、同群或私下饭钱不应成为业务关系，但模型与后处理仍可能遗漏或误判，请人工核对。

## 加密保存与下次打开

点击「加密保存」，设定 **12–256 字符**的独立强密码，点击「加密并下载」。在电脑「下载」或手机「文件」中确认找到 `.dgvault` 后，再点「我已找到保存文件」。后续修改需重新保存；刷新或关闭可能丢失未保存内容。

下次点击「打开文件」，选择 `.dgvault`，输入保存密码，确认替换当前工作台。密码不是微信密码、开机密码或 API 密钥；丢失无法找回。恢复是保存时快照，不重新调用模型，也不代表关系现在仍然有效。

文件包含资料集、导入分析文本、关系、记录和待办，不含 API 密钥、保存密码或上传授权。保存、解密均在浏览器完成；已解锁页面仍可能被同设备用户或恶意插件读取。

[加密工作台示例](../public/examples/demo-workbench.dgvault)的公开密码：`Demo2026!Graph`。仅用于全虚构数据，不可复用于真实客户资料；应通过「打开文件」恢复。

## 限额与隐私

| 对象 | 上限 |
| --- | --- |
| 原始读取 | 10 个文件、合计 20 MB、5 万条消息 |
| 一次所选文本 | 6 万字符，最多 6 批；不是整份原始文件自动上传额度 |
| 单条可发送消息 | 包含发送者／时间包装后不超过 1 万字符；超限需编辑或排除，不静默截断 |
| 确认名单 | 120 个节点 |
| 工作台 | 20 个资料集；加密前内容 10 MB、打开加密文件 16 MB |

线上文本经部署站点的 Cloudflare Worker 发送到所选服务商；本地使用云模型也会外发。选择国内模型不代表全链路境内处理。程序不持久化材料或密钥，不等于平台零保留。请先确认有权处理资料，并查看页面的服务商数据说明。

密钥只暂存页面 30 分钟，移除、切换模型或关闭导入后清除；不会跟随工作台保存。个人笔记和待办不会自动加入模型分析材料。
